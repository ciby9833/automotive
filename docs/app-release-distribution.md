# 移动端安装包发布与分发

## 业务边界

- 只有总部管理员（`HQ_ADMIN`）可以上传和发布安装包、查看发布历史。
- 下载页与 APK 下载接口公开访问，便于未登录用户扫码安装。
- 当前支持 Android APK；平台字段已保留，后续扩展 iOS 企业分发或应用商店链接时无需改写发布历史模型。

## 发布链路

1. 总部管理员在“系统管理 / App 版本维护”选择 APK；页面从 Manifest 自动读取包名、`versionName`、`versionCode` 和 SDK 信息，人工只维护升级策略与版本说明。
2. 后端独立重新解析 APK，以安装包自身版本为准，并校验扩展名、文件大小、包名和版本号唯一性，计算 SHA-256 后上传对象存储。
3. 数据库事务将原正式版归档，并把新版本标记为正式版；历史记录和历史下载地址保持有效。
4. `/app-download` 读取当前正式版，展示版本、说明、校验值、直接下载链接及对应二维码。

## 接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/app-releases` | 总部管理员 | 上传并发布 APK |
| `GET` | `/app-releases` | 总部管理员 | 查询发布历史 |
| `GET` | `/app-releases/public/latest` | 公开 | 查询当前正式版 |
| `GET` | `/app-releases/:id/download` | 公开 | 流式下载指定历史版本 |
| `POST` | `/app-releases/:id/invalidate` | 总部管理员 | 使指定版本及下载链接立即失效 |

## 部署配置

- `APP_RELEASE_MAX_UPLOAD_MB`：后端接收与业务校验共用的文件上限，默认 300 MB。
- `APP_RELEASE_ANDROID_PACKAGE_NAME`：可选的 Android applicationId 白名单；未配置时以首次发布的 APK 包名为准，后续禁止误传其他 App。
- `NEXT_PUBLIC_API_URL`：生产环境必须配置为手机能够访问的 HTTPS API 域名。下载页中的 APK 链接和二维码均基于该地址生成，不能使用 `localhost` 或内网地址。
- 对象文件通过现有存储抽象保存；更换 MinIO、S3 或兼容存储不影响发布模块。
- 网关需要允许 APK 大文件上传和流式下载，并将请求体上限设置为不小于 `APP_RELEASE_MAX_UPLOAD_MB`。

## 数据与演进约束

- `version_code` 在同一平台内唯一，避免客户端升级顺序歧义。
- 同一平台最多一个 `PUBLISHED` 版本；再次发布会归档旧版本，不覆盖文件。
- SHA-256、原文件名、MIME、文件大小、发布人和发布时间随发布记录固化，便于审计和安装包核验。
- 手工失效会记录操作人和时间，失效版本的下载接口返回 HTTP 410，不能再被公开页选为当前版本。
- 发布失败会删除已上传但未入库的孤立对象；归档记录不自动删除，后续如需清理应通过独立保留策略实现。
