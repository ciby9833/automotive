# 总部机构管理

入口：总部账号 → 系统管理 → 机构管理（`/settings/organizations`）。
管理接口同时校验当前有效 membership 的角色、功能权限和总部根机构。JWT 中的角色不能替代数据库中的有效授权。

## 创建测试机构

1. 新建机构，通常选择总部作为上级，与现有业务机构同级。业务账号只访问当前机构，不因上下级关系自动获得其他机构数据。
2. 填写唯一编码、名称、默认币种、IANA 时区和业务日切时间。
3. 在角色管理为该机构创建业务岗位角色，再在用户管理创建“机构范围”账号并分配角色；已有账号可增加机构成员关系，各机构分别授权。ORG_ADMIN 仅为数据范围类型，不自动授予管理员全部功能。
4. 使用该机构的业务账号维护场地 → 区 → 库位、客户及地址簿、供应商及司机/车辆；总部不代做业务维护。新机构不复制原机构的业务数据。

新建机构与运营策略在同一事务中提交。快照开关及预警阈值继承上级，但以后独立维护，不动态跟随上级变更。

## 维护边界

- 根机构仅可改名称和允许修改的运营策略，不可改编码、上级、币种或停用。
- 编码统一去首尾空格并转大写，大小写不敏感唯一；不允许空名称和非法时区。
- 上级不能是自身或后代。存在成员、子机构、业务或历史记录时，不允许改上级。
- 存在业务或历史记录时，不允许换币种、改时区或业务日切。历史快照保留生成时的策略。
- 停用仅用于尚未投入使用的机构：不能有成员、子机构、场地、合作方、业务或历史记录。无强制停用和物理删除功能。
- 停用机构保留在总部维护列表，从业务机构下拉和快照调度中排除。
- 总部查询范围为根机构及后代，业务账号仅为当前机构；场地账号进一步限定到当前成员关系绑定的场地。跨机构、撤权、停用的回归见测试，不代表未覆盖的业务分支已全部证明安全。

## 回归验证

`backend/test/organizations.e2e-spec.ts` 使用真实 HTTP、认证和 PostgreSQL，覆盖权限、编码并发冲突、字段校验、树关系、启停、快照保护和创建失败回滚。初始化链路覆盖新机构管理员登录、场地/区/库位、客户和供应商创建，以及上述列表的同级机构隔离。

测试必须使用已迁入当前 schema、没有业务数据的独立临时库，名称限定为 `alms_org_test_<数字>`；不得指向开发业务库。

```sh
cd backend
ORG_TEST_DB=alms_org_test_<数字> npm run test:e2e -- --runInBand organizations.e2e-spec.ts
npm test -- --runInBand
npm run build
cd ../frontend
npm run build
```

每轮测试需要全新的临时库；测试结束后由创建者清理。`1790100000000-MembershipAuthorization` 将场地绑定从账号迁到机构成员关系；`1790200000000-ConfigurableAccessRoles` 把成员许可转换为可配置机构角色并删除旧权限字段。运行时只有角色授权这一套来源。
